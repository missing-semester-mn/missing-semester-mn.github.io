## Гарын товчлуур дахин оноох {#keyboard-remapping}

Програмист хүний хувьд гар бол мэдээлэл оруулах гол хэрэгсэл тань. Компьютерийн
бараг бүх зүйлийн адил гараа ч тохируулж болно (бас тохируулах нь зүйтэй).

Хамгийн энгийн тохиргоо бол товчлууруудыг дахин оноох (remap). Ихэвчлэн цаана
нь ажиллаж байгаа програм тодорхой товч дарагдахыг барьж аваад, түүнийг өөр
товч дарагдсан мэтээр сольж өгдөг. Жишээ нь:
- Caps Lock-ийг Ctrl эсвэл Escape болгох. Бид (багш нар) үүнийг их зөвлөдөг:
  Caps Lock гарын хамгийн эвтэйхэн байрлалд байдаг ч бараг хэрэглэгддэггүй.
- PrtSc-г хөгжим тоглуулах/зогсоох товч болгох. Ихэнх үйлдлийн системд ийм
  товч бий.
- Ctrl болон Meta (Windows эсвэл Command) товчийг хооронд нь солих.

Товчлуурт дурын команд оноож ч болно. Байнга хийдэг ажилд их хэрэгтэй. Энд
програм тодорхой товчны хослолыг хүлээж байгаад, дарагдахад нь скрипт
ажиллуулна.
- Шинэ терминал эсвэл хөтчийн цонх нээх.
- Байнга бичдэг урт текстийг автоматаар оруулах (жишээ нь имэйл хаяг, оюутны
  дугаар).
- Компьютер эсвэл дэлгэцээ унтраах горимд оруулах.

Үүнээс ч нарийн тохиргоо хийж болно:
- Товчны дараалалд үйлдэл оноох, жишээ нь Shift-ийг таван удаа дарахад Caps
  Lock асах.
- Товчийг хурдан дарж тавих, дараад барих хоёрт өөр үйлдэл оноох. Жишээ нь Caps
  Lock-ийг хурдан дарж тавьбал Esc, бусад товчтой хамт дарж барьбал Ctrl болох.
- Гар эсвэл програм бүрд өөр өөр тохиргоо хийх.

Эхлэхэд туслах хэдэн програм:
- macOS - [karabiner-elements](https://karabiner-elements.pqrs.org/),
  [skhd](https://github.com/koekeishiya/skhd) эсвэл
  [BetterTouchTool](https://folivora.ai/)
- Linux - [xmodmap](https://wiki.archlinux.org/title/Xmodmap) эсвэл
  [Autokey](https://github.com/autokey/autokey)
- Windows - Control Panel-ийн суурь тохиргоо,
  [AutoHotkey](https://www.autohotkey.com/) эсвэл
  [SharpKeys](https://www.randyrants.com/category/sharpkeys/)
- QMK - Хэрэв таны гар өөрийн firmware суулгахыг дэмждэг бол
  [QMK](https://docs.qmk.fm/)-ээр өөрчлөлтөө гар дээрээ шууд хадгалж болно.
  Тэгвэл ямар ч компьютерт залгасан тохиргоо тань хэвээрээ ажиллана.

## Дэмонууд {#daemons}

"Дэмон" (daemon) гэдэг үгийг сонсож байгаагүй ч санаа нь танд аль хэдийн танил
байх. Ихэнх компьютер дээр хэрэглэгч шууд харилцдаггүй, цаана нь байнга
ажилладаг хэд хэдэн процесс бий. Тэднийг дэмон гэдэг, дэмон болж ажилладаг
програмын нэр ихэвчлэн `d`-ээр төгсдөг. Жишээ нь `sshd` бол SSH-ийн дэмон:
гаднаас ирж буй SSH хүсэлтийг хүлээж аваад, хэрэглэгч нэвтрэх эрхтэй эсэхийг
шалгадаг.

Linux дээр системийн дэмонуудыг ажиллуулж, тохируулахад ихэвчлэн `systemd`
хэрэглэдэг. Одоо ямар дэмонууд ажиллаж байгааг `systemctl status`-аар харж
болно. Ихэнх нь танд танихгүй сонсогдох ч сүлжээ удирдах, DNS хүсэлт шийдэх,
графикийн интерфейс харуулах гэх мэт системийн чухал ажлуудыг хариуцдаг.
`systemctl`-аар үйлчилгээнүүдийг `enable`, `disable`, `start`, `stop`,
`restart` хийх, төлөвийг нь шалгах боломжтой.

Илүү сонирхолтой нь `systemd` шинэ дэмон (үйлчилгээ) үүсгэж тохируулахад их
эвтэйхэн. Доор энгийн Python програм ажиллуулах дэмоны тохиргоо байна. Нарийн
тайлбарлахгүй, талбаруудын нэрээс нь юу хийдэг нь ойлгомжтой.

```ini
# /etc/systemd/system/myapp.service
[Unit]
Description=My Custom App
After=network.target

[Service]
User=foo
Group=foo
WorkingDirectory=/home/foo/projects/mydaemon
ExecStart=/usr/bin/local/python3.7 app.py
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

Програмаа тогтмол давтамжтай ажиллуулах гэж байгаа бол тусдаа дэмон бичих
шаардлагагүй. Системд аль хэдийн ажиллаж байгаа, яг ийм хуваарьт ажилд
зориулсан [`cron`](https://www.man7.org/linux/man-pages/man8/cron.8.html)
дэмоныг хэрэглэж болно.

## FUSE {#fuse}

Орчин үеийн програм хангамж ихэвчлэн хооронд нь холбосон жижиг хэсгүүдээс
бүрддэг. Файлын системийн дэмждэг үйлдлүүд нийтлэг "хэл"-ээр тодорхойлогддог
болохоор таны үйлдлийн систем өөр өөр файлын системтэй ажиллаж чаддаг. Жишээ нь
`touch`-аар файл үүсгэхэд `touch` цөм (kernel) рүү системийн дуудлага хийж файл
үүсгэ гэж хэлнэ, цөм нь тухайн файлын системд тохирох дуудлагыг хийж файлыг
үүсгэнэ. Гэхдээ UNIX дээр файлын системийг уламжлал ёсоор цөмийн модуль болгож
хэрэгжүүлдэг тул зөвхөн цөм файлын системийн дуудлага хийж чаддаг.

[FUSE](https://en.wikipedia.org/wiki/Filesystem_in_Userspace) (Filesystem in
User Space)-ээр файлын системийг энгийн хэрэглэгчийн програмаар хэрэгжүүлж
болно. FUSE файлын системийн дуудлагуудыг хэрэглэгчийн бичсэн код руу
дамжуулаад, хариуг нь цөмийн интерфейс рүү буцааж холбоно. Энгийнээр хэлбэл
файлын системийн дуудлага бүр дээр та дурын логик хэрэгжүүлж болно гэсэн үг.

Жишээ нь FUSE-ээр ийм зүйл хийж болно: виртуал файлын систем дээр файлын үйлдэл
хийх болгонд тэр үйлдлийг SSH-ээр алсын машин руу дамжуулж, тэнд гүйцэтгээд, үр
дүнг нь танд буцааж өгнө. Ингэхэд таны програмууд файлыг өөрийн компьютер дээр
байгаа мэт харна, гэтэл үнэндээ тэр алсын машин дээр байгаа. `sshfs` яг үүнийг
хийдэг.

FUSE файлын системийн сонирхолтой жишээнүүд:
- [sshfs](https://github.com/libfuse/sshfs) - Алсын файл, хавтаснуудыг SSH-ээр
  өөрийн компьютер дээр нээх.
- [rclone](https://rclone.org/commands/rclone_mount/) - Dropbox, GDrive,
  Amazon S3, Google Cloud Storage зэрэг үүлэн санг холбож (mount), өгөгдлөө
  энгийн файл шиг нээх.
- [gocryptfs](https://nuetzlich.net/gocryptfs/) - Шифрлэлттэй давхарга файлын
  систем. Файлууд шифрлэгдсэн хэлбэрээр хадгалагдана, харин файлын системийг
  холбосон үед энгийн текст хэлбэрээр харагдана.
- [kbfs](https://keybase.io/docs/kbfs) - Төгсгөл хоорондын шифрлэлттэй тархмал
  файлын систем. Хувийн, дундын, нийтийн хавтастай болж болно.
- [borgbackup](https://borgbackup.readthedocs.io/en/stable/usage/mount.html) -
  Давхардлыг нь арилгасан, шахсан, шифрлэсэн нөөц хуулбараа холбоод амархан
  гүйлгэж үзэх.

## Нөөцлөлт {#backups}

Нөөцлөөгүй өгөгдөл тань яг одоо ч алга болоход бэлэн байгаа өгөгдөл. Өгөгдөл
хуулах амархан, харин найдвартай нөөцлөх хэцүү. Доор нөөцлөлтийн сайн туршлага,
зарим аргын сул талыг дурдъя.

Нэгдүгээрт, өгөгдлийг нэг диск дотор нь өөр газар хуулах нь нөөцлөлт биш, учир
нь тэр диск эвдэрвэл бүгд хамт алга болно. Үүнтэй адил гэртээ байгаа гадаад диск
ч гал түймэр, хулгай гэх мэт гамшгаас хамгаалахгүй тул хуулбараа өөр газар
хадгалахыг зөвлөдөг.

Синхрончлол бол нөөцлөлт биш. Жишээ нь Dropbox/GDrive эвтэйхэн, гэхдээ өгөгдөл
устсан эсвэл эвдэрсэн бол тэр өөрчлөлт шууд синхрончлогдоод л алга болно. Яг
ийм шалтгаанаар RAID шиг дискийг толин хуулбарладаг шийдэл ч нөөцлөлт биш.
Файлаа устгах, эвдэх, ransomware-т шифрлүүлэх үед RAID таныг аврахгүй.

Сайн нөөцлөлтийн гол шинж нь хувилбаржуулалт, давхардал арилгалт, аюулгүй
байдал. Хувилбаржуулалт байвал өөрчлөлтийн түүхээс файлаа хуучин төлөвт нь
сэргээж болно. Сайн нөөцлөлтийн систем давхардлыг арилгаж, зөвхөн өөрчлөгдсөн
хэсгийг хадгалснаар зай хэмнэдэг. Аюулгүй байдлын хувьд өөрөөсөө "Миний
өгөгдлийг унших, эсвэл бүр дордвол бүх өгөгдөл, нөөцийг минь устгахад хэн нэгэнд
юу мэдэх, юу эзэмших хэрэгтэй вэ?" гэж асуугаарай. Эцэст нь нөөцдөө сохроор
итгэх нь муу санаа. Нөөцөөсөө өгөгдөл сэргээж чадаж байгаа эсэхээ тогтмол
шалгаж байх хэрэгтэй.

Нөөцлөлт зөвхөн компьютер дээрх файлаар хязгаарлагдахгүй. Вэб програмууд огцом
өссөнөөр таны ихэнх өгөгдөл зөвхөн үүлэнд хадгалагдаж байна. Жишээ нь эдгээр
системд хаягаа алдвал имэйл, сошиал сүлжээний зургууд, хөгжмийн жагсаалт, онлайн
баримт бичгүүд тань хамт алга болно. Ийм өгөгдлийнхөө офлайн хуулбартай байх нь
зүйтэй. Онлайнаас ийм өгөгдлийг татаж авдаг бэлэн хэрэгслүүд олон бий.

Дэлгэрэнгүйг 2019 оны [Нөөцлөлт](/2019/backups) лекцийн тэмдэглэлээс үзээрэй.

## API {#apis}

Энэ хичээлээр компьютерээ өөр дээрээ хийх ажилд илүү үр дүнтэй ашиглах талаар
их ярьсан. Гэхдээ эдгээр аргын ихэнх нь интернэтэд ч ажилладаг. Ихэнх онлайн
үйлчилгээ өгөгдөлдөө програмаар хандуулдаг "API"-тай. Жишээ нь
АНУ-ын засгийн газар цаг агаарын мэдээ авах API-тай, үүгээр шелл дээрээ цаг
агаараа амархан харж болно.

Ихэнх API ойролцоо бүтэцтэй. Ихэвчлэн `api.service.com` маягийн URL байх ба
зам, асуулгын параметрээр ямар өгөгдөл унших, ямар үйлдэл хийхийг заадаг. Жишээ
нь АНУ-ын цаг агаарын API-аас тодорхой байршлын мэдээ авахын тулд
https://api.weather.gov/points/42.3604,-71.094 руу GET хүсэлт (жишээ нь
`curl`-ээр) явуулна. Хариунд нь тухайн бүсийн цаг агаарын мэдээ авах өөр
холбоосууд ирнэ. Хариу ихэвчлэн JSON форматтай байдаг тул
[`jq`](https://stedolan.github.io/jq/) зэрэг хэрэгслээр өөрт хэрэгтэй хэлбэрт
оруулж болно.

Зарим API нэвтрэлт шаарддаг. Ихэвчлэн хүсэлттэйгээ нууц *токен* явуулдаг.
Тухайн API-ийн баримт бичгийг уншиж юу шаарддагийг нь мэдээрэй, гэхдээ хамгийн
түгээмэл нь "[OAuth](https://www.oauth.com/)" протокол. Товчхондоо OAuth танд
тухайн үйлчилгээ дээр таны нэрийн өмнөөс тодорхой үйлдэл хийж чадах нууц токен
өгдөг. Эдгээр токен *нууц* гэдгийг санаарай: токеныг тань авсан хүн таны нэрээр
түүний зөвшөөрсөн бүх үйлдлийг хийж чадна!

[IFTTT](https://ifttt.com/) бол API-ийн санаан дээр суурилсан вэб үйлчилгээ.
Үүгээр олон үйлчилгээний үйл явдлыг үйлдэлтэй холбож автоматжуулж болно.
Сонирхоод үзээрэй!

## Командын мөрийн түгээмэл флаг, хэв маяг {#common-command-line-flagspatterns}

Командын мөрийн хэрэгслүүд хоорондоо их ялгаатай тул хэрэглэхээсээ өмнө `man`
хуудсыг нь уншиж байх хэрэгтэй. Гэхдээ нийтлэг шинжүүд бий:

 - Ихэнх хэрэгсэл `--help` маягийн флагтай, энэ нь товч хэрэглээний зааврыг
   харуулна.
 - Буцааж болохгүй өөрчлөлт хийдэг олон хэрэгсэл "туршилтын ажиллагаа" (dry run)
   горимтой: юу ч өөрчлөхгүйгээр юу хийх гэж байгаагаа л *хэвлэнэ*. Мөн устгах
   үйлдэл бүрийн өмнө асуудаг "интерактив" флагтай байх нь элбэг.
 - Хэрэгслийн хувилбарыг ихэвчлэн `--version` эсвэл `-V`-ээр харна (алдааны
   мэдээлэл бичихэд хэрэг болно!).
 - Бараг бүх хэрэгсэл илүү дэлгэрэнгүй гаралт өгөх `--verbose` эсвэл `-v`
   флагтай. Флагийг олон удаа давтвал (`-vvv`) бүр дэлгэрэнгүй гаралт авна,
   дебаг хийхэд их хэрэгтэй. Эсрэгээрээ `--quiet` флаг ихэвчлэн зөвхөн алдаа
   гарвал хэвлэдэг болгодог.
 - Ихэнх хэрэгсэлд файлын нэрийн оронд `-` бичвэл аргументаас хамаараад
   стандарт оролт эсвэл стандарт гаралт гэсэн утгатай.
 - Аюултай байж болох хэрэгслүүд анхдагчаараа рекурсив биш, харин рекурсив
   болгох флагтай (ихэвчлэн `-r`).
 - Заримдаа флаг шиг харагдах зүйлийг энгийн аргумент болгож дамжуулах хэрэг
   гардаг. Жишээ нь `-r` нэртэй файл устгах, эсвэл нэг програмаар дамжуулж өөр
   програм ажиллуулах (`ssh machine foo` гэх мэт) үед дотоод програмд нь флаг
   өгөх. Тэр үед тусгай `--` аргумент хэрэглэнэ: түүний араас ирэх бүх зүйлийг
   флаг биш, энгийн аргумент гэж үзнэ. Жишээ нь `rm -- -r` эсвэл
   `ssh machine --for-ssh -- foo --for-foo`.

## Цонхны менежер {#window-managers}

Та бүхний ихэнх Windows, macOS, Ubuntu-гийн анхдагч цонхны менежер шиг "чирж
тавьдаг" цонхны менежерт дассан байх. Цонхнууд дэлгэц дээр бие биенээ давхардан
хөвж, чирж, хэмжээг нь өөрчилж болдог. Үүнийг "хөвөгч" (floating) цонхны менежер
гэдэг. Гэхдээ ялангуяа Linux дээр өөр төрлийн цонхны менежер олон бий. Түгээмэл
нэг хувилбар нь "хавтанцар" (tiling) цонхны менежер. Ийм менежерт цонхнууд
хэзээ ч давхцахгүй, харин дэлгэц дээр яг tmux-ийн хэсгүүд шиг хавтанцар мэт
хуваагдаж байрлана. Дэлгэц нээлттэй цонхнуудаар үргэлж дүүрэн байх ба сонгосон
байрлалын схемийн дагуу өөрчлөгдөнө. Ганц цонх нээлттэй бол дэлгэцийг бүтэн
эзэлнэ. Хоёр дахийг нээхэд эхнийх нь жижгэрч зай тавьж өгнө (жишээ нь 2/3 ба
1/3). Гурав дахийг нээхэд бусад нь дахин жижгэрнэ. tmux-ийн адил цонхнуудынхаа
хооронд хулганад хүрэлгүй гараараа шилжиж, хэмжээг нь өөрчилж болно. Судлаад
үзэхэд гэмгүй!

## VPN {#vpns}

VPN өнөө үед их моодонд орсон, гэхдээ үүнд [ямар нэг баттай
шалтгаан](https://web.archive.org/web/20230710155258/https://gist.github.com/joepie91/5a9909939e6ce7d09e29)
бий эсэх нь эргэлзээтэй. VPN юу өгдөг, юу өгдөггүйг мэдэж байх хэрэгтэй.
Хамгийн *сайн* тохиолдолд VPN бол интернэтийн хувьд таны интернэт үйлчилгээ
үзүүлэгчийг (ISP) л сольж байгаа хэрэг. Таны бүх сүлжээний урсгал бодит
байршлаас тань биш, VPN үйлчилгээ үзүүлэгчээс ирж буй мэт харагдана, харин таны
холбогдсон сүлжээ зөвхөн шифрлэгдсэн урсгал харна.

Сонсоход дажгүй ч VPN хэрэглэснээр та итгэлээ ISP-ээсээ VPN үйлчилгээ
үзүүлэгч рүү л шилжүүлж байна. ISP-ийн тань харж чадах байсан бүхнийг одоо
VPN үйлчилгээ үзүүлэгч *харна*. Тэдэнд ISP-ээсээ илүү итгэдэг бол ашигтай, үгүй
бол ашиг нь тодорхой биш. Нисэх буудлын шифрлэлтгүй, сэжигтэй Wi-Fi дээр сууж
байгаа бол VPN хэрэгтэй байж магадгүй, гэхдээ гэртээ бол тийм ч ойлгомжтой биш.

Мөн өнөөдөр таны нууц мэдээлэл агуулсан сүлжээний урсгалын ихэнх нь HTTPS эсвэл
TLS-ээр *аль хэдийн* шифрлэгдсэн. Ийм үед "муу" сүлжээн дээр байгаа эсэх
тань тийм ч чухал биш: сүлжээний оператор таныг ямар сервертэй холбогдож
байгааг л мэднэ, солилцож буй өгөгдлийг тань харахгүй.

Дээр "хамгийн сайн тохиолдолд" гэснийг анзаараарай. VPN үйлчилгээ үзүүлэгчид
програмаа буруу тохируулснаас шифрлэлт нь сул эсвэл бүр унтраалттай байсан
тохиолдол гарч л байсан. Зарим хорлонтой (эсвэл ядаж боломжийг ашигладаг)
үйлчилгээ үзүүлэгч таны бүх урсгалыг бүртгэж, мэдээллийг тань гуравдагч этгээдэд
зардаг. Муу VPN үйлчилгээ үзүүлэгч сонгох нь VPN огт хэрэглэхгүй байснаас ч дор
байж болно.

Хэрэгтэй бол MIT оюутнууддаа зориулж [VPN ажиллуулдаг](https://ist.mit.edu/vpn).
Өөрийн VPN босгох гэж байгаа бол [WireGuard](https://www.wireguard.com/)-ийг
судлаарай.

## Markdown {#markdown}

Карьерынхаа туршид та текст бичих нь бараг гарцаагүй. Тэгэхдээ ихэнхдээ энгийн
хэлбэржүүлэлт хэрэгтэй болно: зарим үгийг тод, налуу болгох, гарчиг, холбоос,
кодын хэсэг нэмэх гэх мэт. Word, LaTeX шиг хүнд хэрэгсэл хэрэглэхийн оронд хөнгөн
тэмдэглэгээний хэл болох [Markdown](https://commonmark.org/help/)-ыг хэрэглэж
болно.

Та Markdown-ыг, эсвэл ядаж түүний ямар нэг хувилбарыг харж байсан байх. Нэр нь
Markdown биш байсан ч интернэтэд бараг хаа сайгүй дэмждэг. Markdown бол хүмүүс
энгийн текст файл бичихдээ аяндаа хэрэглэдэг байсан тэмдэглэгээг стандарт болгох
гэсэн оролдлого. *Налуу* текстийг үгийн хоёр талд `*` тавьж, **тод** текстийг
`**` тавьж бичнэ. `#`-ээр эхэлсэн мөр гарчиг болох ба `#`-ийн тоо нь гарчгийн
түвшинг заана. `-`-ээр эхэлсэн мөр жагсаалтын мөр, тоо + цэгээр эхэлсэн мөр
дугаартай жагсаалтын мөр болно. Backtick-ээр хүрээлсэн текст `кодын
фонт`-оор харагдана. Кодын блокийг дөрвөн хоосон зайгаар догол оруулах эсвэл
гурвалсан backtick-ээр хүрээлж бичнэ:

```
энд код бичигдэнэ
```

Холбоос нэмэхдээ харагдах *текстийг* дөрвөлжин хаалтанд, URL-ыг араас нь дугуй
хаалтанд бичнэ: `[нэр](url)`. Markdown сурахад хялбар, хаа ч хэрэглэж болно.
Үнэндээ энэ лекцийн болон бусад бүх лекцийн тэмдэглэл Markdown-аар бичигдсэн,
энэ хуудасны эх кодыг [эндээс](https://raw.githubusercontent.com/missing-semester/missing-semester/master/_2020/potpourri.md)
харж болно.

## Hammerspoon (macOS дээрх автоматжуулалт) {#hammerspoon-desktop-automation-on-macos}

[Hammerspoon](https://www.hammerspoon.org/) бол macOS-ийн ширээний
автоматжуулалтын фреймворк. Үйлдлийн системийн функцүүдтэй холбогддог Lua
скрипт бичиж болно. Тэр скриптүүд гар, хулгана, цонх, дэлгэц, файлын систем гэх
мэт олон зүйлтэй харилцаж чадна.

Hammerspoon-оор хийж болох хэдэн жишээ:

- Цонхнуудыг тодорхой байрлал руу зөөх товчлол оноох.
- Цонхнуудыг тодорхой байрлалаар автоматаар байрлуулдаг цэсний мөрний товч
  үүсгэх.
- Лабд ирэхэд (WiFi сүлжээг нь таньж) чанга яригчаа автоматаар хаах.
- Найзынхаа цэнэглэгчийг андуурч авсан бол анхааруулга харуулах.

Ерөнхийдөө Hammerspoon товч дарах эсвэл ямар нэг үйл явдал болоход дурын Lua код
ажиллуулж чаддаг, мөн системтэй харилцах олон сантай тул хийж болох зүйл
бараг хязгааргүй. Олон хүн Hammerspoon-ий тохиргоогоо нээлттэй хуваалцсан
байдаг тул тэднээс санаа авч болно, эсвэл өөрөө эхнээс нь бичиж ч болно.

## Ачаалал ба Live USB {#booting--live-usbs}

Компьютер асахад үйлдлийн систем ачаалагдахаас өмнө
[BIOS](https://en.wikipedia.org/wiki/BIOS)/[UEFI](https://en.wikipedia.org/wiki/Unified_Extensible_Firmware_Interface)
техник хангамжаа бэлддэг. Энэ үед тодорхой товч дарж BIOS-ийн тохиргоо руу орж
болно. Жишээ нь компьютер асахдаа "Press F9 to configure BIOS. Press F12 to
enter boot menu." гэж харуулж магадгүй. BIOS цэснээс техник хангамжтай холбоотой
бүх төрлийн тохиргоо хийж болно. Мөн ачаалах цэс (boot menu) руу орж ердийн
дискийнхээ оронд өөр төхөөрөмжөөс ачаалж болно.

[Live USB](https://en.wikipedia.org/wiki/Live_USB) бол дотроо үйлдлийн
системтэй флаш диск. Үйлдлийн системийн дүрсийг (image), жишээ нь Linux
дистрибутивыг татаж аваад флаш диск рүү бичиж үүсгэдэг. Энэ нь `.iso` файлыг
диск рүү хуулахаас арай өөр. Үүнд [UNetbootin](https://unetbootin.github.io/)
шиг live USB үүсгэгч програм хэрэглэдэг.

Live USB олон зүйлд хэрэг болдог. Жишээ нь үйлдлийн систем тань эвдэрч
ачаалахаа больсон бол live USB-ээр системээ сэргээх эсвэл өгөгдлөө хуулж авч
болно.

## Docker, Vagrant, VM, үүлэн үйлчилгээ, OpenStack {#docker-vagrant-vms-cloud-openstack}

[Виртуал машин](https://en.wikipedia.org/wiki/Virtual_machine) (VM) болон
контейнер зэрэг ижил төстэй хэрэгслүүд үйлдлийн системтэй нь хамт бүтэн
компьютерийн системийг дуурайж чадна. Энэ нь туршилт хийх, хөгжүүлэлт
хийх, итгэлгүй кодыг тусгаарлагдсан орчинд ажиллуулахад хэрэгтэй.

[Vagrant](https://www.vagrantup.com/) бол машины тохиргоог (үйлдлийн систем,
үйлчилгээ, багц гэх мэт) кодоор тодорхойлоод, `vagrant up` гэж л VM үүсгэдэг
хэрэгсэл. [Docker](https://www.docker.com/) санааны хувьд төстэй, гэхдээ
контейнер ашигладаг.

Үүлнээс VM түрээсэлж ч болно. Энэ нь дараах үед хэрэгтэй:

- Үйлчилгээ байршуулахад зориулсан, нийтийн IP хаягтай, байнга асаалттай хямд
  машин
- CPU, диск, RAM, GPU ихтэй машин
- Өөрт байгаагаас хамаагүй олон машин (ихэвчлэн секундээр төлбөр авдаг тул 1000
  машиныг хэдхэн минутаар түрээслээд их тооцоо хийж болно)

Түгээмэл үйлчилгээ үзүүлэгчид: [Amazon AWS](https://aws.amazon.com/), [Google
Cloud](https://cloud.google.com/), [Microsoft Azure](https://azure.microsoft.com/),
[DigitalOcean](https://www.digitalocean.com/).

MIT CSAIL-ийн гишүүн бол судалгааны зорилгоор [CSAIL OpenStack
instance](https://tig.csail.mit.edu/shared-computing/open-stack/)-аас үнэгүй VM
авч болно.

## GitHub {#github}

[GitHub](https://github.com/) бол нээлттэй эхийн хөгжүүлэлтийн хамгийн алдартай
платформуудын нэг. Энэ хичээлээр үзсэн [vim](https://github.com/vim/vim)-ээс
эхлээд [Hammerspoon](https://github.com/Hammerspoon/hammerspoon) хүртэлх олон
хэрэгсэл GitHub дээр бий. Өдөр бүр хэрэглэдэг хэрэгслүүдээ сайжруулахад
туслаад нээлттэй эхэд хувь нэмрээ оруулж эхлэх их амархан.

GitHub дээрх төсөлд хувь нэмэр оруулах хоёр үндсэн арга бий:

- [Issue](https://help.github.com/en/github/managing-your-work-on-github/creating-an-issue)
  үүсгэх. Үүгээр алдаа мэдээлэх эсвэл шинэ боломж хүсэх боломжтой. Аль нь ч код
  унших, бичих шаардлагагүй тул харьцангуй хөнгөн, гэхдээ сайн бичсэн алдааны
  мэдээлэл хөгжүүлэгчдэд маш их үнэ цэнэтэй. Байгаа хэлэлцүүлэгт санал нэмэх нь
  ч тустай.
- [Pull request](https://help.github.com/en/github/collaborating-with-issues-and-pull-requests/about-pull-requests)-ээр
  код оруулах. Ерөнхийдөө issue үүсгэхээс илүү их ажил. GitHub дээр репог
  [fork](https://help.github.com/en/github/getting-started-with-github/fork-a-repo)
  хийгээд, өөрийн хуулбар дээрээ шинэ салаа үүсгэж, өөрчлөлтөө (жишээ нь алдаа
  засах, боломж нэмэх) хийж, салаа руугаа push хийгээд, дараа нь үндсэн репо
  руу [pull request үүсгэнэ](https://help.github.com/en/github/collaborating-with-issues-and-pull-requests/creating-a-pull-request).
  Үүний дараа төслийг хариуцагчидтай ярилцана, тэд таны кодонд санал өгнө. Бүх
  юм болчихвол таны код merge хийгдэнэ. Том төслүүд ихэвчлэн хувь нэмэр оруулах
  зааварчилгаатай, эхлэгчдэд тохирох issue-үүдийг тэмдэглэсэн байдаг, зарим нь
  бүр зөвлөх багштай хөтөлбөртэй.
