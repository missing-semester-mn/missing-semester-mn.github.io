Өгөгдлийг нэг форматаас өөр формат руу хувиргах хэрэг гарч байсан уу? Гарч л
таарна! Энэ лекц яг үүний тухай: текст эсвэл хоёртын өгөгдлийг яг өөрт хэрэгтэй
хэлбэрт оруулах хүртэл нь боловсруулах.

Өмнөх лекцүүдэд өгөгдөл цэгцлэх (data wrangling) энгийн жишээнүүдийг аль хэдийн
үзсэн. Үнэндээ `|` оператор хэрэглэх болгондоо та өгөгдөл цэгцэлж л байгаа.
Жишээ нь `journalctl | grep -i intel` командыг авъя. Энэ нь системийн бүх
логоос Intel гэсэн үг орсон мөрүүдийг (том жижиг үсэг ялгахгүй) шүүж харуулна.
Үүнийг өгөгдөл цэгцлэх гэж бодохгүй байж магадгүй, гэхдээ нэг форматаас
(системийн бүх лог) өөрт илүү хэрэгтэй формат руу (зөвхөн intel-ийн лог)
хувиргаж байгаа нь тэр. Өгөгдөл цэгцлэхийн гол нь ямар хэрэгслүүд байдгийг
мэдэх, тэднийг яаж хослуулахаа ойлгох.

Эхнээс нь эхэлье. Өгөгдөл цэгцлэхэд хоёр зүйл хэрэгтэй: боловсруулах өгөгдөл,
түүн дээр хийх үйлдэл. Лог файл бол сайн жишээ, учир нь тэднээс тодорхой
мэдээлэл хайх хэрэг байнга гардаг, бүгдийг нь нэг бүрчлэн уншаад суух боломжгүй.
Миний сервер рүү хэн нэвтрэх гэж оролдож байгааг логоос нь харъя:

```bash
ssh myserver journalctl
```

Хэтэрхий их мэдээлэл гарлаа. Зөвхөн ssh-тэй холбоотойг нь үлдээе:

```bash
ssh myserver journalctl | grep sshd
```

Анзаарсан уу: *алсын* серверийн файлыг урсгаж, өөрийн компьютер дээрх
`grep`-ээр шүүж байна! `ssh` үнэхээр гайхалтай хэрэгсэл, дараагийн командын
мөрийн орчны лекцээр дэлгэрэнгүй ярина. Гэхдээ одоо ч бидэнд хэрэгтэйгээс
хамаагүй их мэдээлэл байгаа, уншихад ч төвөгтэй хэвээр. Сайжруулъя:

```bash
ssh myserver 'journalctl | grep sshd | grep "Disconnected from"' | less
```

Яагаад нэмэлт хашилт хэрэглэв? Лог маань их том байж болно, бүгдийг нь
компьютер руугаа урсгаж байж шүүх нь сүлжээ, цаг хоёуланг нь дэмий үрнэ.
Тиймээс шүүлтээ алсын сервер дээр нь хийгээд, үр дүнг нь л өөр лүүгээ татна.
`less` бол урт гаралтыг дээш доош гүйлгэж уншуулдаг "хуудаслагч" (pager).
Командаа туршиж, янзлах явцдаа сүлжээгээ хэмнэхийн тулд шүүсэн логоо өөрийн
компьютер дээр файлд хадгалаад түүн дээрээ ажиллаж болно:

```console
$ ssh myserver 'journalctl | grep sshd | grep "Disconnected from"' > ssh.log
$ less ssh.log
```

Энд хэрэггүй мэдээлэл одоо ч их байна. Үүнийг цэвэрлэх *маш олон* арга бий,
гэхдээ таны хэрэгслийн хайрцгийн хамгийн хүчтэй хэрэгслүүдийн нэг болох
`sed`-тэй танилцъя.

`sed` бол хуучны `ed` засварлагч дээр суурилсан "урсгалын засварлагч" (stream
editor). Түүнд файлын агуулгыг шууд засахын оронд түүнийг яаж өөрчлөхийг богино
командуудаар зааж өгдөг. Команд нь олон, гэхдээ хамгийн их хэрэглэгддэг нь `s`
буюу орлуулах (substitution) команд. Жишээ нь:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed 's/.*Disconnected from //'
```

Бидний сая бичсэн зүйл бол энгийн *regular expression* (товчоор regex). Regex
нь текстийг тодорхой загвартай (pattern) тааруулдаг хүчтэй хэрэгсэл. `s` команд
`s/REGEX/SUBSTITUTION/` хэлбэртэй: `REGEX` нь хайх загвар, `SUBSTITUTION` нь
олдсон текстийг солих шинэ текст.

(Энэ бичиглэлийг Vim [лекцийн тэмдэглэлийн](/2020/editors/#advanced-vim)
"Хайж солих" хэсгээс таньж байж магадгүй! Vim `sed`-ийн орлуулах командтай
төстэй бичиглэл хэрэглэдэг. Нэг хэрэгсэл сурах нь бусдыг нь илүү сайн эзэмшихэд
ихэвчлэн тусалдаг.)

## Regular expression

Regex маш түгээмэл, бас хэрэгтэй тул яаж ажилладгийг нь ойлгоход цаг гаргах нь
зүйтэй. Дээр хэрэглэсэн `/.*Disconnected from /`-оос эхэлье. Regex-ийг ихэвчлэн
(үргэлж биш) `/`-ээр хүрээлж бичдэг. Ихэнх ASCII тэмдэгт зүгээр л өөрийгөө
илэрхийлдэг, харин зарим нь тусгай утгатай. Аль тэмдэгт ямар утгатай болох нь
regex-ийн хэрэгжүүлэлт бүрд бага зэрэг өөр байдаг нь их толгой өвтгөдөг.
Хамгийн түгээмэл загварууд:

 - `.` шинэ мөрөөс бусад "дурын нэг тэмдэгт".
 - `*` өмнөх тэмдэгт тэг буюу түүнээс олон удаа давтагдана.
 - `+` өмнөх тэмдэгт нэг буюу түүнээс олон удаа давтагдана.
 - `[abc]` `a`, `b`, `c`-гийн аль нэг тэмдэгт.
 - `(RX1|RX2)` `RX1` эсвэл `RX2`-той таарах аль нэг нь.
 - `^` мөрийн эхлэл.
 - `$` мөрийн төгсгөл.

`sed`-ийн regex жаахан хачин: дээрх тэмдэгтүүдийн ихэнхэд тусгай утгаа өгөхийн
тулд өмнө нь `\` тавих хэрэгтэй. Эсвэл `-E` флаг өгч болно.

Тэгэхээр `/.*Disconnected from /`-г дахин харвал энэ нь дурын тооны тэмдэгтээр
эхэлж, араас нь "Disconnected from " гэсэн текст орсон аливаа текстэй таарна.
Бидэнд яг үүнийг л хэрэгтэй, гэхдээ regex их зальтай гэдгийг санаарай. Хэн нэгэн
"Disconnected from" гэсэн хэрэглэгчийн нэрээр нэвтрэх гэж оролдвол яах вэ?
Тэгвэл бид ийм мөр харна:

```
Jan 17 03:13:00 thesquareplanet.com sshd[2631]: Disconnected from invalid user Disconnected from 46.97.239.16 port 55920 [preauth]
```

Юу үлдэх вэ? `*`, `+` хоёр анхдагчаараа "шунахай" (greedy): боломжтой хамгийн
урт текстийг барьж авна. Тиймээс энд ийм үр дүн гарна:

```
46.97.239.16 port 55920 [preauth]
```

Бидний хүссэн зүйл энэ биш байх. Зарим regex хэрэгжүүлэлтэд `*`, `+`-ийн ард
`?` нэмээд "шунахай бус" болгож болдог, харамсалтай нь `sed` үүнийг
дэмждэггүй. Харин perl-ийн командын мөрийн горим дэмждэг тул түүн рүү шилжиж
болно:

```bash
perl -pe 's/.*?Disconnected from //'
```

Гэхдээ цаашдаа `sed`-ээ үргэлжлүүлэн хэрэглэнэ, учир нь ийм ажилд хамгийн
түгээмэл хэрэгсэл нь энэ. `sed` өөр олон зүйл хийж чадна: таарсан мөрүүдийг
хэвлэх, нэг дуудлагаар олон орлуулалт хийх, хайх гэх мэт. Гэхдээ энд тэр
бүгдийг нарийн үзэхгүй. `sed` өөрөө том сэдэв, гэхдээ ихэнхдээ түүнээс илүү
тохирох хэрэгсэл олддог.

За, одоо хэрэглэгчийн нэрийн ард байгаа хэсгийг арилгах хэрэгтэй. Яаж хийх вэ?
Хэрэглэгчийн нэрийн араас орох текстийг яг тааруулах нь амаргүй, ялангуяа нэр
дотор хоосон зай байж болох юм бол! Харин *бүтэн* мөрийг тааруулах хэрэгтэй:

```bash
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user .* [^ ]+ port [0-9]+( \[preauth\])?$//'
```

[Regex шалгагч](https://regex101.com/r/qqbZqh/2) дээр юу болж байгааг харъя.
Эхлэл нь өмнөхтэй адилхан. Дараа нь "user"-ийн хувилбаруудыг тааруулж байна
(логт хоёр төрлийн угтвар байдаг). Дараа нь хэрэглэгчийн нэр байх хэсэгт дурын
тэмдэгтүүдийг тааруулна. Тэгээд дурын нэг үгийг тааруулна (`[^ ]+`; хоосон
зайгүй, хоосон биш дурын тэмдэгтийн цуваа). Дараа нь "port" гэсэн үг, араас нь
тоон цуваа. Эцэст нь байж ч болох, байхгүй ч байж болох `[preauth]` дагавар
болон мөрийн төгсгөл.

Ингэвэл "Disconnected from" гэсэн хэрэглэгчийн нэр биднийг төөрөгдүүлэхээ болино.
Яагаад гэдгийг ойлгож байна уу?

Гэхдээ нэг асуудал бий: лог бүхэлдээ хоосон болчихлоо. Бид хэрэглэгчийн нэрийг
*үлдээх* ёстой байсан шүү дээ. Үүний тулд "барих бүлэг" (capture group)
хэрэглэнэ. Хаалтанд хийсэн regex-тэй таарсан текст дугаартай барих бүлэгт
хадгалагдана. Тэднийг орлуулах хэсэгт (зарим хэрэгжүүлэлтэд загвар дотор ч)
`\1`, `\2`, `\3` гэх мэтээр дуудаж болно. Тэгэхээр:

```bash
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/'
```

Таны таамаглаж байгаачлан *маш* төвөгтэй regex бичиж болно. Жишээ нь [имэйл
хаягийг](https://www.regular-expressions.info/email.html) яаж тааруулах тухай
нийтлэл бий. [Тийм ч амар
биш](https://web.archive.org/web/20221223174323/http://emailregex.com/). Энэ
талаар [маш их
маргаан](https://stackoverflow.com/questions/201323/how-to-validate-an-email-address-using-a-regular-expression/1917982)
өрнөдөг. Хүмүүс бүр
[тест](https://fightingforalostcause.net/content/misc/2006/compare-email-regex.php),
[тестийн матриц](https://mathiasbynens.be/demo/url-regex) хүртэл бичсэн.
Өгсөн тоо [анхны тоо мөн
эсэхийг](https://www.noulakaz.net/2007/03/18/a-regular-expression-to-check-for-prime-numbers/)
шалгадаг regex ч бичиж болно.

Regex-ийг зөв бичих хэцүү, гэхдээ хэрэгслийн хайрцагтаа заавал байх ёстой их
хэрэгтэй зүйл!

## Өгөгдөл цэгцлэх рүүгээ буцъя

Одоо бидэнд ийм команд байна:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/'
```

`sed` өөр олон сонирхолтой зүйл хийж чадна: текст оруулах (`i` команд),
мөрүүдийг тусгайлан хэвлэх (`p` команд), дугаараар нь мөр сонгох гэх мэт.
Дэлгэрэнгүйг `man sed`-ээс үзээрэй!

Ямар ч байсан одоо нэвтрэх гэж оролдсон бүх хэрэглэгчийн нэрийн жагсаалт бидэнд
байна. Гэхдээ энэ нь дангаараа тийм ч хэрэгтэй биш. Хамгийн түгээмэл нэрсийг
олъё:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/' \
 | sort | uniq -c
```

`sort` нэрнээсээ л ойлгомжтой, оролтоо эрэмбэлнэ. `uniq -c` дараалсан ижил
мөрүүдийг нэг мөр болгож, өмнө нь хэдэн удаа давтагдсаныг бичнэ. Үүнийгээ
дахин эрэмбэлээд хамгийн түгээмэл 10 нэрийг л үлдээе:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/' \
 | sort | uniq -c \
 | sort -nk1,1 | tail -n10
```

`sort -n` үсгийн биш тоон дарааллаар эрэмбэлнэ. `-k1,1` нь "зөвхөн хоосон
зайгаар тусгаарласан эхний баганаар эрэмбэл" гэсэн үг. `,n` хэсэг нь `n` дэх
талбар хүртэл эрэмбэл гэж заадаг, анхдагчаар мөрийн төгсгөл хүртэл. Энэ
*жишээн* дээр бүтэн мөрөөр эрэмбэлсэн ч ялгаагүй, гэхдээ сурч байгаа хойно мэдэж
байх нь зүйтэй!

Хамгийн *цөөн* давтагдсаныг харах бол `tail`-ийн оронд `head` хэрэглэнэ. Мөн
эсрэг дарааллаар эрэмбэлдэг `sort -r` бий.

За, энэ дажгүй, гэхдээ эдгээр нэрийг тохиргооны файлд хэрэглэх гээд мөр мөрөөр
биш, таслалаар тусгаарласан жагсаалт болгож авах гэвэл яах вэ?

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/' \
 | sort | uniq -c \
 | sort -nk1,1 | tail -n10 \
 | awk '{print $2}' | paste -sd,
```

macOS хэрэглэж байгаа бол: дээрх команд macOS-д дагалддаг BSD-ийн `paste` дээр
ажиллахгүй. BSD болон GNU coreutils-ийн ялгаа, macOS дээр GNU coreutils яаж
суулгах талаар [шеллийн хэрэгслүүдийн лекцийн 4-р
дасгалаас](/2020/shell-tools/#exercises) үзээрэй.

Эхлээд `paste`-ээс эхэлье: энэ нь мөрүүдийг (`-s`) өгсөн нэг тэмдэгтээр
(`-d`; энд `,`) нийлүүлдэг. Харин `awk` гэж юу вэ?

## awk -- бас нэг засварлагч

`awk` бол текстийн урсгал боловсруулахад маш сайн тохирсон програмчлалын хэл.
`awk`-ийн тухай ярих юм *их* бий, гэхдээ бусад олон зүйлийн адилаар энд зөвхөн
үндсийг нь үзнэ.

Эхлээд `{print $2}` юу хийдэг вэ? `awk` програм нь заавал биш загвар, мөн тэр
загвар мөртэй таарвал юу хийхийг заасан блокоос бүрдэнэ. Анхдагч загвар
(бидний дээр хэрэглэсэн) бүх мөртэй таарна. Блок дотор `$0` нь бүтэн мөрийг,
`$1`-ээс `$n` нь тухайн мөрийн `n` дэх *талбарыг* заана. Талбаруудыг `awk`-ийн
талбар тусгаарлагчаар (анхдагч нь хоосон зай, `-F`-ээр сольж болно) хуваадаг.
Энд бид мөр бүрийн хоёр дахь талбар буюу хэрэглэгчийн нэрийг хэвлэж байна!

Илүү сонирхолтой зүйл хийж үзье. `c`-ээр эхэлж `e`-ээр төгссөн, зөвхөн нэг удаа
нэвтрэх гэж оролдсон хэрэглэгчийн нэр хэд байгааг тоолъё:

```bash
 | awk '$1 == 1 && $2 ~ /^c[^ ]*e$/ { print $2 }' | wc -l
```

Задлаад үзэх юм нэлээд байна. Эхлээд загвар (`{...}`-ийн өмнөх хэсэг) байна.
Энэ нь эхний талбар 1-тэй тэнцүү (энэ бол `uniq -c`-ийн тоолуур), хоёр дахь
талбар өгсөн regex-тэй таарах ёстой гэж заана. Блок нь зүгээр л нэрийг хэвлэнэ.
Дараа нь гарсан мөрүүдийг `wc -l`-ээр тоолно.

Гэхдээ `awk` програмчлалын хэл гэдгийг санаж байгаа биз?

```awk
BEGIN { rows = 0 }
$1 == 1 && $2 ~ /^c[^ ]*e$/ { rows += $1 }
END { print rows }
```

`BEGIN` бол оролтын эхэнд таардаг загвар (`END` нь төгсгөлд). Мөр бүр дээр
ажиллах блок одоо эхний талбарын утгыг нэмж (энд үргэлж 1 байх ч гэсэн),
төгсгөлд нь нийлбэрийг хэвлэнэ. Үнэндээ `grep`, `sed`-ийг `awk`-ээр [бүрэн
орлуулж](https://web.archive.org/web/20251210045942/https://backreference.org/2010/02/10/idiomatic-awk/)
болно, гэхдээ үүнийг танд дасгал болгож үлдээе.

## Өгөгдлөө шинжлэх

Стандарт оролтоос уншдаг тооны машин болох `bc`-ээр шелл дээрээ шууд тооцоо
хийж болно! Жишээ нь мөр бүрийн тоог `+`-ээр холбоод нэмэх:

```bash
 | paste -sd+ | bc -l
```

Эсвэл арай төвөгтэй илэрхийлэл:

```bash
echo "2*($(data | paste -sd+))" | bc -l
```

Статистик гаргах олон арга бий. [`st`](https://github.com/nferraz/st) их
хэрэгтэй, харин [R](https://www.r-project.org/) суулгасан бол:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/' \
 | sort | uniq -c \
 | awk '{print $1}' | R --no-echo -e 'x <- scan(file="stdin", quiet=TRUE); summary(x)'
```

R бол өгөгдөл шинжлэх, [график зурахад](https://ggplot2.tidyverse.org/) их сайн
бас нэг (жаахан хачирхалтай) програмчлалын хэл. Нарийн ярихгүй, гэхдээ
`summary` нь векторын статистик хураангуйг хэвлэдэг. Бид оролтын тоонуудаас
вектор үүсгэсэн тул R бидэнд хэрэгтэй статистикийг гаргаж өгч байна!

Энгийн график хэрэгтэй бол `gnuplot` тусална:

```bash
ssh myserver journalctl \
 | grep sshd \
 | grep "Disconnected from" \
 | sed -E 's/.*Disconnected from (invalid |authenticating )?user (.*) [^ ]+ port [0-9]+( \[preauth\])?$/\2/' \
 | sort | uniq -c \
 | sort -nk1,1 | tail -n10 \
 | gnuplot -p -e 'set boxwidth 0.5; plot "-" using 1:xtic(2) with boxes'
```

## Өгөгдөл цэгцлээд аргумент бэлдэх

Заримдаа урт жагсаалтаас суулгах эсвэл устгах зүйлсээ олохын тулд өгөгдөл
цэгцлэх хэрэг гардаг. Өмнө үзсэн аргуудаа `xargs`-тай хослуулбал маш хүчтэй
болно.

Жишээ нь лекц дээр үзүүлсэнчлэн миний систем дээрх Rust-ийн хуучин nightly
хувилбаруудыг олж, нэрийг нь ялгаж аваад, `xargs`-аар устгах команд руу
дамжуулж болно:

```bash
rustup toolchain list | grep nightly | grep -vE "nightly-x86" | sed 's/-x86.*//' | xargs rustup toolchain uninstall
```

## Хоёртын өгөгдөл боловсруулах

Одоог хүртэл ихэвчлэн текст өгөгдлийн тухай ярилаа, гэхдээ пайп хоёртын
өгөгдөлд ч адилхан хэрэгтэй. Жишээ нь ffmpeg-ээр камераасаа зураг авч, саарал
болгож, шахаад, SSH-ээр алсын машин руу явуулж, тэнд нь задлаад, хуулбар
хадгалж, дэлгэц дээр харуулж болно.

```bash
ffmpeg -loglevel panic -i /dev/video0 -frames 1 -f image2 - \
 | convert - -colorspace gray - \
 | gzip \
 | ssh mymachine 'gzip -d | tee copy.jpg | env DISPLAY=:0 feh -'
```

# Дасгал ажил

1. Энэ [богино интерактив regex хичээлийг](https://regexone.com/) хийж үзээрэй.
1. `/usr/share/dict/words` дотор дор хаяж гурван `a` агуулсан, `'s`-ээр
   төгсөөгүй үг хэд байгааг олоорой. Эдгээр үгийн хамгийн түгээмэл сүүлийн хоёр
   үсэг юу вэ? Том жижиг үсгийн ялгааг арилгахад `sed`-ийн `y` команд эсвэл `tr`
   програм тусална. Тэр хоёр үсгийн хослол тус бүр хэд байна вэ? Нэмэлт сорилт:
   аль хослолууд огт гарахгүй байна вэ?
1. Файлыг шууд засах гэж `sed s/REGEX/SUBSTITUTION/ input.txt > input.txt` гэж
   бичих нь элбэг. Гэхдээ яагаад энэ муу санаа вэ? Зөвхөн `sed`-д хамаатай
   асуудал уу? Үүнийг зөв хийх аргыг `man sed`-ээс олоорой.
1. Сүүлийн арван ачааллын (boot) дундаж, медиан, хамгийн удаан хугацааг
   олоорой. Linux дээр `journalctl`, macOS дээр `log show` ашиглаад ачаалал
   бүрийн эхлэл, төгсгөлийн логийн цагийг хараарай. Linux дээр эдгээр нь ийм
   харагдаж болно:
   ```
   Logs begin at ...
   ```
   болон
   ```
   systemd[577]: Startup finished in ...
   ```
   macOS дээр [ийм харагдаж
   болно](https://eclecticlight.co/2018/03/21/macos-unified-log-3-finding-your-way/):
   ```
   === system boot:
   ```
   болон
   ```
   Previous shutdown cause: 5
   ```
1. Сүүлийн гурван ачааллын хооронд *давхцахгүй* байгаа ачааллын мессежүүдийг
   олоорой (`journalctl`-ийн `-b` флагийг үзээрэй). Энэ ажлыг хэд хэдэн алхамд
   хуваагаарай. Эхлээд сүүлийн гурван ачааллын логийг л авах аргаа олоорой.
   Таны хэрэглэж буй хэрэгсэлд үүнд зориулсан флаг байж болно, эсвэл
   `sed '0,/STRING/d'` хэрэглээд `STRING`-тэй таарахаас өмнөх бүх мөрийг устгаж
   болно. Дараа нь мөр бүрийн *үргэлж* өөрчлөгддөг хэсгийг (жишээ нь цагийн
   тэмдэг) арилгаарай. Тэгээд оролтын мөрүүдийг давхардалгүй болгож, тус бүрийн
   тоог гаргаарай (`uniq` танд тусална). Эцэст нь тоо нь 3 болсон мөрүүдийг
   хасаарай (учир нь тэд гурван ачаалалд бүгдэд нь байсан).
